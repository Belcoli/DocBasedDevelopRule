# 插件制作计划

目标：按 [设计基线](design.md) 制作可审阅、可验证的独立 Codex 插件。本文只分解制作工作，不定义插件行为，也不记录实际完成度。

## 约束

遵守设计基线，尤其是主契约独占有效设计、项目资料不进入插件、单技能入口、无运行工具硬依赖。已有设计确认覆盖本计划的常规制作；改变设计基线时先说明影响。制作不包含自动提交、推送、发布或修改用户已有安装。

## 文件与职责

- `plugins/document-first-development/`：可安装包；清单、一个技能入口、规则、流程、空白模板。
- `.agents/plugins/marketplace.json`：仓库分发目录。
- `README.md`、`docs/install.md`、`docs/maintenance.md`：使用、安装与维护指引。
- `docs/design.md`：插件制作设计基线。
- `validation/scenarios.md`、`validation/report.md`：虚构场景与实际验证记录。
- `scripts/validate_package.py`：维护者可选结构检查，非运行依赖。

## 制作任务

### 1. 规则和职责

输入为设计基线；产物为技能入口和 references。明确设计提案归属、门禁与设计的区别、授权和任务裁剪。用仅调查、契约冲突和未知设计场景检查行为。

### 2. 流程与模板

接入、开发、审核交接流程消费同一组核心规则。模板只包含对应文档职责允许的字段。检查 Progress/Issues 无设计字段，提案无生效权威；已有项目映射保留原文件位置。

### 3. 包装与说明

清单与 marketplace 使用一致的稳定名称，所有运行内容随包分发。安装指南区分同包兼容与客户端实测；迁移只更换本地定位。检查包内相对路径和资源闭合。

### 4. 验证与收尾

执行结构检查及负向夹具，独立演练代表性场景，核对项目资料隔离。可隔离完成的 CLI 安装加载不触碰用户原有配置；桌面安装或会话测试未执行时如实记录。实际结果只记验证报告。

## 重点复核

- Progress 或 Issue 是否被误用为设计来源。
- 新用户决策与旧主契约冲突时是否正确修订。
- 只读任务是否被自动扩大为实施或文档修改。
- 局部问题是否错误阻断无关开发。
- 项目实例、主机路径或工具依赖是否进入插件。

计划可由维护者使用现有工具执行；不要求安装任何配套制作技能。
