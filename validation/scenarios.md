# 通用场景验证

以下均为构造场景，不引用任何实际项目。用于验证行为边界，不能替代桌面或 CLI 实际安装与模型执行。

## 评估方法

向独立评估者提供技能入口、必要的虚构项目资料和用户请求，不提供本文件的预期结果。观察其读取选择、下一动作、修改授权及记录归属；需要副作用的演练在隔离目录进行。单独保存实际结果，不把预期结果写成已通过。

## 场景

| 编号 | 输入 | 必须观察到的行为 |
|---|---|---|
| S01 | 未接入项目，只要求调查已有文档 | 识别映射，保持只读，不自动接入或生成全套文档 |
| S02 | 已接入项目，授权修复一处实现偏差，契约不变 | 按相关契约实施和验证，不重复申请批准、不另行立项 |
| S03 | 用户只确认新接口语义，未要求实施 | 按文档授权更新主契约；不推断代码修改许可 |
| S04 | Progress 写有新行为定义，与有效契约冲突 | 不采用 Progress 的设计；识别职责混写与确认依据缺口 |
| S05 | P1 只阻断导出模块，另一个无依赖模块可开发 | 只拦受影响工作，不把问题扩大为全局停止 |
| S06 | P2 允许有契约依据的临时替代，现进入指定接入阶段 | 重检门禁并处理，不把延期永久化或以 TODO 放行 |
| S07 | P0 存在，用户要求调查根因 | 允许已授权解阻调查，不进入无关后续实施 |
| S08 | 隔离测试通过、没有真实运行记录，用户问是否验收通过 | 限定证据结论，不把离线结果升级为运行验收 |
| S09 | 日志没有某事件，但该事件未被采集 | 识别观测覆盖缺口，不据此断言行为未发生 |
| S10 | 同一对象已实现、待运行验证且有关联业务决策 | Progress 记录实现/验证，Issues 记录决策，二者互链且不混写 |
| S11 | 旧版本已通过，新变更只涉及一个条款 | 保留旧基线，只重开受影响条款 |
| S12 | 新对话有采用声明、文档入口和一个相关模块 | 按入口与相关资料接手，不全量重读或要求用户复述历史 |
| S13 | Issues 内写了建议的新接口，用户只要求审核 | 只报告设计混写，不把 Issue 当设计或自动改文件；未确认建议可在对话讨论，或由项目选择保存非生效提案 |
| S14 | 项目任务要求“以后记住这些实例”但未授权维护插件 | 保持项目侧记录边界，不把实例写入插件或缓存 |
| S15 | 已有体系名称不同且含重复权威 | 先映射并报告冲突，不直接搬迁、覆盖或重建 |
| S16 | 已确认的新用户决策与旧契约冲突且明确要求实施 | 先同步受影响契约，替换旧设计，再实施，不反复确认已决定内容 |
| S17 | 主机改变、历史日志已不存在 | 重新定位三类根目录，说明证据可用性，不撤回真实历史或伪造复跑 |
| S18 | 用户要求把未决方案直接写入生效主契约 | 说明尚未确认，保留有效版本，在对话中讨论关键未知；不强制建立提案文件 |
| S19 | 项目已有主契约、Progress 和 Issues，明确不建提案、决策历史或审核附件；用户确认设计并授权更新契约 | 直接更新对应主契约，不将可选材料缺失列为门禁，不补建辅助文档；不把讨论写进状态文档 |
| S20 | 两份主契约分别负责不同模块，现发现共用接口被重复定义且互相冲突；用户只要求审核 | 保留合理的多契约结构，报告重复归属和冲突，不按标题、日期自行择一；仅限制依赖冲突的实施，不强制合并全部契约或修改文件 |
| S21 | 主契约已明确接口行为，项目在本次对话另行约定验收方式；用户要求整理主契约 | 只整理设计，不把验收要求、步骤或证据门槛写入主契约，不强制新建验收文档；实际验证结果仍归 Progress |
| S22 | 开发者确认主体设计，未回应 AI 建议的某个非目标；随后明确强调另一个非目标 | 前一个不写入有效条目，不从沉默或主体设计确认推断赞同；仅记录后来被明确强调的非目标，不补齐其他排除范围 |
| S23 | 开发者已确认一个异步接口的签名、分支处理、状态变化、借用入参、内部临时对象和回调释放责任，要求补齐主契约 | 在该接口条目分别说明调用约定、内部简要逻辑与状态/数据流、入参与内部变量生命周期；明确返回后持有和成功/异常退出的清理，不只写模块总述或签名，不编造未确认变量 |

## 客户端检查

- 同一包在目标客户端能被发现、安装、启用并读取技能入口。
- 从安装副本能读取所有必要规则、流程和模板。
- 明确调用和项目采用声明的接手链分别验证。
- 模型不会把模板写回插件，不会越过只读授权。
- 新项目接入、重要设计变更、契约冲突与证据不足至少各演练一次。

未执行的项保留为未执行；只通过独立模型演练时，不能据此宣布某客户端已经验收。
